# The Roadmap

## Short Form (Checklist)

- [x] Install `cargo-watch`, `sqlx-cli`, and add the `wasm32-wasi` target.
- [x] Initialize the project folders (`core`, `runner`, `guests`) and root `Cargo.toml` workspace.
- [x] Create `.env` and `docker-compose.yml`.
- [ ] Run `docker-compose up -d` to start Postgres.
- [ ] Run `sqlx database create` and `sqlx migrate add init` to setup the DB schema.
- [ ] Build the `core` crate (DB connection pool, error handling).
- [ ] Build a simple "Hello World" Rust function in the `guests` folder and compile it to Wasm.
- [ ] Build the `runner` crate (Axum server + Wasmtime integration) to load and execute the Wasm file.
- [ ] Wire the `runner` to save execution logs/metrics to the database via `core`.
- [ ] Test the full loop via `curl` or Postman.

## Detailed Form (Step-by-Step)

**Step 1: Infrastructure & Database Initialization**
Start your database with Docker. Once it's running, use `sqlx-cli` to create your initial database tables. You'll want a table called `executions` to track every time a function runs (storing the function name, duration, and status code). This gives your project real observability.

**Step 2: The `core` Crate (Foundation)**
Write your database connection logic here using `sqlx::PgPool`. Define your custom errors using the `thiserror` crate. By keeping this separate from the web server, you ensure your domain logic is clean and testable.

**Step 3: The `guests` Crate (The Payload)**
Move into the `guests/guest_hello_world` folder. Write a simple Rust script that reads from standard input (stdin) and prints to standard output (stdout). Run `cargo build --target wasm32-wasi`. Copy the resulting `.wasm` file into a `guests_compiled` folder at your project root.

**Step 4: The `runner` Crate (The Engine)**
Set up an Axum server in `runner/src/main.rs`. Create a POST route like `/execute/:function_name`.
Inside `runner/src/engine/`, write the Wasmtime logic:

1. Initialize the Wasmtime `Engine` and `Store`.
2. Configure WASI so the guest can read stdin and write stdout.
3. Load the `.wasm` file matching the `function_name` from the URL.
4. Execute it, capture the stdout, and return it as the HTTP response.

**Step 5: Tying it Together (The Dev Loop)**
Open a terminal and run `cargo watch -x 'run -p runner'`. This starts your Axum server. Send a POST request to your local server. The Axum server will intercept the request, spin up the Wasmtime sandbox, execute your compiled guest Wasm, log the execution time to your Postgres database, and return the result.

## Professional Workspace Structure

In a production environment, you don't put everything in one `src/main.rs`. You use a **Cargo Workspace** to split your code into distinct, manageable crates.

_Important Note:_ Your "Guest" functions (the `.wasm` files) should live in a **completely separate folder/workspace** from your Host. If you mix them, `cargo build` will get confused trying to compile an Axum web server to WebAssembly.

```text
my_serverless_platform/
├── .env                      # Environment variables
├── docker-compose.yml        # Infrastructure setup
├── Cargo.toml                # Workspace definition (for host + core)
├── migrations/               # SQL files generated by sqlx-cli
│
├── core/                     # CRATE: Shared business logic
│   ├── Cargo.toml
│   └── src/
│       ├── lib.rs            # Exports modules
│       ├── db.rs             # Database connection pooling
│       ├── models.rs         # Structs representing DB tables
│       └── error.rs          # Custom AppError using thiserror
│
├── runner/                   # CRATE: The Host Application
│   ├── Cargo.toml
│   └── src/
│       ├── main.rs           # Tokio runtime entry point
│       ├── api/              # Axum HTTP routes
│       └── engine/           # Wasmtime setup, sandboxing, and execution
│
└── guests/                   # FOLDER: The Wasm Functions (Independent)
    ├── guest_image_resizer/  # A standalone Cargo project
    │   ├── Cargo.toml        # Compiles ONLY to wasm32-wasi
    │   └── src/main.rs
    └── guest_hello_world/
```
